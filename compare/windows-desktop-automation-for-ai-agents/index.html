Windows desktop automation for AI agents: Anode, BgDesk, Windows-MCP, Desktop Touch MCP, windows-computer-use-mcp and Terminator compared

Checked on 24 October 2026: two of these six Windows desktop-automation MCP servers, Anode and BgDesk, run the agent in a separate Windows session (a child session) with its own pointer and keyboard focus, while Windows-MCP, Desktop Touch MCP, windows-computer-use-mcp and Terminator act in your own session, and each of those four has click paths that move your real pointer. We read the five besides Anode from their docs and source code and did not run them. A third route, used by Ghost, lowlevel-computer-use-mcp and computer-use-plus, drives apps with window messages (Ghost and computer-use-plus also use UI Automation), starting them on a hidden desktop in your session: by default it leaves your pointer alone, but some apps ignore message input. In Anode's live validation of version 0.11.1 (2 October 2026), with your real pointer over Anode's hidden viewer, Windows' Remote Desktop control tried 7 times to copy the agent's pointer moves to your pointer, and Anode blocked all 7; the 0.11.3 release passed its 112 quick checks for this page. Method, sources and data are below.

We make Anode. Read this as a vendor's page: our own numbers come from real runs that you can repeat, and everything about the other tools links to where we read it. If we got something wrong, open an issue and we will correct it.

The short answer

  • You want to keep using your mouse and keyboard while the agent works on the same PC: Anode or BgDesk. Both give the agent a child session, a second Windows session for your account with its own screen, pointer and keyboard focus, where its clicks and typing land. Anode has more tools (41, including UI Automation reads, command jobs, display changes and Android emulators) and one seat per Windows session that your agents share in turn. BgDesk has 13 tools and splits its session into up to 12 areas, so several agents work at once, and a local web page shows each one and lets you take it over.
  • You want the agent to work on your own desktop while you watch: Windows-MCP, the most starred of these (10,216 GitHub stars) and listed in Claude's connector directory. Its 0.8.8 control gate pauses the agent when you use the mouse or keyboard (details below); to run it where your input doesn't reach it, see Windows-MCP in the background.
  • You want the agent in your session but without moving your pointer where it can: Ghost works through window messages and UI Automation, with real input off unless you turn it on in its settings; lowlevel-computer-use-mcp and computer-use-plus work in the background on a hidden desktop. Desktop Touch MCP's click_element and Terminator's invoke_element act through UI Automation without moving the pointer, though Terminator brings the target window to the front by default; their mouse tools, Terminator's click_element (which puts the pointer back), Desktop Touch's browser_click, and Desktop Touch's desktop_act DevTools and mouse routes move it. Some apps ignore message input.
  • You are on Windows Home, or can't run an administrator step: not Anode, and probably not BgDesk. Both use child sessions, which Anode's install guide says Windows Home can't host (BgDesk's README names no editions and says editions other than the one it was developed on are untested), and both need an administrator step once. Windows-MCP and the tools that act in your session name no edition limit.
  • You need a security boundary for untrusted work: none of these. Use a virtual machine or Windows Sandbox.

Each tool, and when to choose it over Anode

Windows-MCP

CursorTouch/Windows-MCP is a Python MCP server with 21 tools, including Snapshot (the UI Automation tree), Screenshot, Click, Type, PowerShell, Registry and FileSystem. It is listed in Claude's connector directory. It works in your session: its Click moves the real cursor before pressing, and Type clicks its target first. Its 0.8.8 release (10 October 2026) added a control gate: during each call and for 15 seconds after it, it holds back your keyboard and mouse; a substantial mouse move or Ctrl+Alt+Shift+Backspace takes control back, and once the agent has been idle for 15 seconds any input does (so does any input while it hides its indicator to take a screenshot). It then refuses new calls until you have left the mouse and keyboard alone for 10 seconds. A screen edge and a cursor glow show when the agent has control, and its README calls the takeover best-effort. Its main branch has an opt-out and gate policies (#458, #466) that no release carries yet. Its security notes say it is not sandboxed and suggest a VM or Windows Sandbox. Anonymous telemetry is on until you set ANONYMIZED_TELEMETRY=false.

Choose it when you are happy to watch the agent work on your own desktop, are on Windows Home (where Anode can't run; Windows-MCP needs Python 3.14, which runs on Windows 10 and 11, and names no editions), want the most starred project here, or want shell, registry and file tools in the same server. To keep its tools while your own input stays in your session, where its gate shouldn't see it (so far tested with nobody at the PC), run it inside Anode's seat: Windows-MCP in the background. Choose Anode when you want to keep working while the agent clicks.

Desktop Touch MCP

Harusame64/desktop-touch-mcp is a TypeScript server with a native Rust core and 32 tools. It mixes routes. desktop_act tries UI Automation (Invoke and Value), then the DevTools protocol, which finds a browser element and clicks it with the real mouse, then terminal input (for Windows Terminal, a paste it asks you to approve each time), and finally a real mouse click at the element. click_element uses UI Automation Invoke only, which its guide says works without moving the cursor; since 2.3.2 its docs say not to use it on list, tree or grid items. mouse_click, mouse_drag, scroll at a given point and browser_click move the real mouse, animated by default; browser_click first brings the browser window to the front, and since 2.3.2 it refuses to click when another window covers the point. Its keyboard tool brings the target window to the front by default, except background typing into terminal-class windows, and a forceFocus option forces a window forward when Windows refuses. Parking the mouse in the top-left corner stops it.

Choose it for UI Automation-first work in your own session, Chrome pages over the DevTools protocol, terminal input, its Excel tool, or a macOS preview. Choose Anode when apps need real mouse and keyboard input and you don't want that input on your desktop.

windows-computer-use-mcp

sandraschi/windows-computer-use-mcp is a Python server built on pywinauto, with 20 tools (22 with two opt-in ones), plus a local web UI and a desktop app. Its mouse tool and coordinate clicks move the real pointer in either dispatch mode; element clicks go through pywinauto, and an opt-in "background" mode tries UI Automation Invoke first but falls back to a real click. Its mouse and keyboard tools are refused until approve_automation is called, which opens a 5-minute window by default (an environment variable bypasses it, and also turns off the corner abort below). The project calls this human-in-the-loop, but the agent can call that tool itself, so a person checks it only if your MCP client asks you to approve the call; element clicks and text entry aren't gated. Moving the pointer to the top-left corner aborts pointer actions. Its safety doc calls desktop automation "host-powerful", says the server doesn't start Windows Sandbox, and suggests a separate virtualisation server for isolation.

Choose it when you want an approval call before its mouse and keyboard tools, a local operator UI, or pywinauto's control coverage. Choose Anode when nobody should have to step away from the PC.

Terminator

mediar-ai/terminator is a Rust automation library with an MCP server (terminator-mcp-agent, 35 tools), from Mediar. Its README lists "Doesn't take over your cursor or keyboard" among its features. Its source at 73a381c shows that the click_element tool moves the real pointer with SendInput to click and then puts it back by default (restore_cursor), and that its action tools bring the target window to the front by default; most restore your keyboard focus afterwards, but click_element and invoke_element don't unless asked. mouse_drag moves the pointer too, and its typing tools click the target, without putting the pointer back, when focusing fails. invoke_element (UI Automation Invoke) is the route that doesn't move the pointer. A stop_execution tool cancels running tools, and a full-screen action overlay is on by default. PostHog usage analytics (always built in) and Sentry error reports (a default build feature) are on by default; environment variables turn both off. Its optional OmniParser and Gemini vision modes call Mediar's hosted service by default.

Choose it when you want its Rust automation library as well as the MCP server, its Chrome extension in your own signed-in browser, or Mediar's workflow builder and managed hosting for teams. Choose Anode when the agent's clicks and windows must stay off your desktop.

BgDesk

enwong93-sketch/background-computer-use (BgDesk, "Background Computer Use for Windows") is a C# MCP server, at release 2.0.0 since 17 October 2026, that uses the same Windows feature as Anode: a child session, a loopback Remote Desktop session under your own logon, turned on with WTSEnableChildSessions and hosted, off-screen, in Microsoft's Remote Desktop control. Its tagline says "hidden desktop"; its "How it works" section explains that this is a child session, a second desktop with its own input queue where SendInput works as it does for a person. That makes it a separate Windows session, not a hidden Win32 desktop like those of the tools under Hidden desktops and other routes. An agent process inside that session sends real mouse and keyboard input there, or window messages for app types it has tested (Chromium, Electron, Explorer, consoles and classic dialogs). The session's one large screen is divided into up to 12 areas of 1440x900, one per agent, so several agents can work at once. A local web page (bgdesk workplace, on 127.0.0.1 behind a token) shows each area live with a timeline of actions and lets you take an area over, and an ask_user tool hands logins, captchas and payments to you. It needs an account with a password and an administrator step once, and keeps the password in Windows Credential Manager after the first sign-in. Its README says bgdesk enable only turns on child sessions, leaving inbound Remote Desktop as you had it; Anode's setup also turns on the Remote Desktop listener, without opening the firewall. Its README lists its tests, run on Windows 11 Enterprise, says other editions are untested, and documents limits: no elevated windows, no whole-screen shortcuts, and message input that some controls ignore, which it checks for afterwards and can repeat as real input.

Choose it when several agents should work side by side, you want to watch and take over each one from a browser page, or you want later starts to sign in silently (it stores the password). Choose Anode when you need its wider tool set (UI Automation reads and waits, command jobs, display changes, audio, gamepads and Android emulators), a published record of live checks for each release since 0.9, with their scripts in its repository, or would rather type your Windows password when Windows asks than have it stored.

Anode's limits

  • Windows 10/11 Pro, Enterprise or Education, or Windows Server with the Remote Desktop host, on x64. Windows Home can't host a child session.
  • anode setup needs one administrator prompt; it turns on Remote Desktop and child sessions and can restart Remote Desktop Services (what it changes).
  • One seat per Windows session, shared by your agents in turn.
  • Windows may refuse to sign the seat in automatically; then you sign it in from the tray icon with your Windows password (it happened in the 0.11.3 release check). A PIN or Windows Hello sign-in may not work there.
  • The seat runs as you, with your files, accounts and network: desktop isolation, not a security sandbox.
  • The seat runs unelevated, so elevated windows may ignore its input, and UAC prompts inside the seat are awkward.
  • Apps that allow one copy may already be open in your own session; browsers need a separate profile.
  • Builds are unsigned, so SmartScreen may warn. Anode is young and has few users so far (3 GitHub stars).

Hidden desktops and other routes

In our discovery test of 22 October, AI agents asked to find a Windows MCP server that works in the background picked lowlevel-computer-use-mcp and computer-use-plus, and named Ghost and WindowsPC-MCP as alternatives (they also named BgDesk, in the table above). umbriel came up in a directory listing during our searches. All read from their README and source (umbriel from its README only) at the commits under Sources, not run by us.

  • Ghost (Northtek; MIT, 28 stars, 0.23.4 of 6 September 2026, 54 tools on Windows) drives the windows on your desktop with window messages and UI Automation, and starts the apps it launches on a hidden desktop in your session. Real mouse and keyboard input is off by default, and only you can turn it on, in the server's settings: GHOST_FOCUS_POLICY sets it, and GHOST_FOCUS_LOCK=off lets the agent switch it with a tool call. So by default it doesn't move your pointer. Chromium can still take the foreground for a moment, and Ghost hands it back: across six runs of about 490 keystrokes with a person typing, its README counts one keystroke that reached the wrong window. Ctrl+Alt+G stops every acting call. Its README says real input doesn't work on its hidden desktop, so apps that need real input need its foreground policy, on your own desktop.
  • lowlevel-computer-use-mcp (4 stars; MIT in its README, no licence file; automated GitHub releases, the latest of 14 October 2026 at the commit read; 59 tools) starts apps on hidden Win32 desktops and clicks and types there with posted window messages, without moving your pointer; its tools that do move it run only when the agent passes confirm_focus_disruption=true. Its README says some apps ignore message input and that its install and release process "remain unverified", and its GUI installer turns on auto-approval of all its tools in Claude Code by default.
  • computer-use-plus (MIT, 2 stars, no release, last commit 15 August 2026; README in Chinese) works only on its own hidden desktop by default ("backgroundOnly"), through UI Automation and window messages, and never switches your screen to it, so there is no view of it for you. An opt-in foreground mode moves the real pointer.
  • WindowsPC-MCP (MIT, 1 star, no release, last commit 27 May 2026) shows the agent's apps on a virtual monitor (Parsec's virtual display driver) and a hidden desktop. Its README says "Your monitors are untouched", but for each batch of real input its source switches the session's input desktop to the agent's desktop and back, and a comment there says switching on every input flickered for the user.
  • umbriel (MIT, 2 stars, no GitHub release; npm 1.14.0 of 27 June 2026; last commit 15 August 2026) drives windows in your session through UI Automation and posted messages. Its README says invoke, scroll, set-value and toggle move no cursor, even on hidden windows and minimised classic Win32 windows, that typing and real clicks need an unlocked desktop, and that its SendInput fallback briefly takes the foreground.
  • Cua Driver, Desktop Commander and Windows 365 for Agents are compared in Anode's When to use Anode, and when to use something else.
